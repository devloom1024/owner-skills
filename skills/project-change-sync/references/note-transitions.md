# 决策记录变更检查

使用本次范围预检和所有权解析结果，不因布局差异扩大审计范围。

## 动作与证据

- 同时核对源/目标路径规则；源路径已删除时从已验证的比较基线读取原规则和内容。无法取得时报告证据缺口，不只检查移动后的目录。
- 区分纯路径移动、状态转换、决策变更和首次归档；不同动作不能仅靠文件名或 Git 的重命名判定混为一谈。

## 专项检查

1. **当前 owner**：一个有效决定范围只有一个当前所有者，活跃导航指向实际 owner，不因移动留下可独立维护的重复正文。
2. **内容与替代**：变更保留仍有效的决定和提案；部分替代有明确的剩余范围；整合记录保留独有理由、备选方案、后果和验证缺口。归档有内容依据，而非仅看位置、年龄或字数。
3. **状态语义**：采纳不等于交付，移动不重置记录身份或首次提出日期，也不改变决定；状态转换有实现、否决或撤回证据。`archived/` 可以保留原始 `Status`，不做路径与正文字符串相等检查。
4. **关联文件与引用**：项目已有的翻译、配对元数据和附件完整，必要的活跃入链、可编辑出链、导航及 owner 映射同步。当前理由引用指向当前 owner，历史引用明确其用途。
5. **冻结约束**：首次归档的移动和元数据变化符合项目封存流程；已冻结记录的改写、删除、重新移动或解除冻结有明确依据。

## 验证与判定

只使用已有结果或只读的冻结、配对和链接检查。活跃入链应能定位目标；冻结记录的出链不自动修复，也不要求其反映当前代码。已有检查与封存约束冲突时报告限制，不建议篡改历史或放宽门禁来获得通过。

冻结约束被破坏时单列有证据的违规发现，不能标为已验证的 `covered`。

重复活跃 owner、漏移关联文件或丢失必需引用造成已确认同步缺口时标 `missing`；关键证据不明确时用 `review-required`。纯移动只有在有证据确认不需要更新其他 owner 或引用后，才可标 `not-needed`。
