# 事实验证

当前事实必须有源码、测试、配置、生成器或已运行命令支持。

1. 找到声明对应的 canonical source；
2. 读取相关实现、调用方和测试；
3. 对文档中的命令、配置、默认值、错误和平台行为，在适当环境和授权范围内验证；未运行时说明原因，不以指定负责人代替证据；
4. 分别记录声明来源、验证方式和实际结果；`observed`、`test-backed`、`mechanical`、`review-only` 或 `unknown` 必须说明对应证据或缺口，不把它们当作规范的采纳状态；
5. 编辑模式下先更新事实源，再同步派生文档和生成产物；
6. 只读审计使用现有证据或不会改写文件的 check 模式；需要重新生成才能确认时报告缺口。已授权编辑才按项目流程生成，并检查 freshness、链接和内容；
7. 双语、类型等价、快照和文档预算只按项目已有且与本次修改相关的门禁验证。

未运行命令不能被写成“已验证”；命令失败或环境缺失要写入报告。

涉及开发规范时，另按 [规范形成与采纳](standards-governance.md) 核实项目决定；事实证据或一次检查通过不能替代采纳依据。
