# 文档模型

按文档职责和主题所有者组织项目文档。目录表达职责，文件表达事实或理由，索引负责导航。

## 推荐入口

```text
docs/
├── AGENTS.md
├── README.md
├── architecture.md
├── subsystems/
├── standards/       # 项目需要跨模块规范时启用
├── agent-notes/     # 项目采用 Agent Note 生命周期时启用
├── postmortem/      # 项目需要事故复盘时启用
├── guides/          # 存在可重复操作流程时启用
└── contracts/       # 存在机器可读契约时启用
```

这是一组职责模型，不是必须完整创建的空目录树。已有项目按实际内容和事实所有者判断是否保留。

## 所有权

- 架构地图拥有系统组合和阅读路线。
- 子系统参考拥有当前类型、语义、边界和验证。
- 包 README 拥有包消费者契约、配置、限制和扩展点。
- 设计记录拥有提案、替代方案、决策理由和后果。
- postmortem 拥有事故因果链和预防。
- 规范拥有可执行的审查规则和证据。
- 生成参考由源代码和生成器拥有。
- 索引只导航，不复制事实。

## 内容边界

下列信息按实际主题取用，可并入已有页面或链接到 owner，不要求复制固定模板：

- subsystem：职责和边界、当前运行路径、状态与失败恢复、兼容性及限制、源码位置和验证；无需为不存在的状态机补章节。
- 规范：范围、规则、理由、失败模式、验证和例外；采纳依据与验证方式分别记录，见 [规范形成与采纳](standards-governance.md)。
- postmortem 或项目已有经验记录：现象与影响、根因、修复、如何更早发现和证据；提升为规范需另作判断。
- 契约索引：机器可读 source、生成产物、generator/check 和语义 owner。Schema 不能替代权限、生命周期、顺序、错误及兼容性语义的说明；索引只链接这些 owner。

## 状态

当前文档使用现在时态；设计文档遵循项目已有 ADR/决策生命周期，没有约定时才参考 `proposed`、`implemented`、`rejected`、`archived`。生成物标注 source/generator；候选事实标记来源和置信度，不把采纳的方案等同于已实现行为。
