# 文档模型

按文档职责和主题所有者组织项目文档。目录表达职责，文件表达事实或理由，索引负责导航。

## 推荐入口

```text
docs/
├── AGENTS.md
├── README.md
├── architecture.md
├── subsystems/
├── standards/       # 项目需要跨模块规范时启用
├── postmortem/      # 项目需要事故复盘时启用
├── guides/          # 存在可重复操作流程时启用
└── contracts/       # 存在机器可读契约时启用

.agents/
└── notes/          # 有持久提案或决策时启用
```

这是一组职责模型，不是必须完整创建的空目录树。除 Notes 根目录外，路径按项目实际组织；不为了满足示例创建没有内容的文件。

## 决策记录位置

项目根下 `.agents/notes/` 是本库约定的唯一活跃决策记录根，架构类记录承担 ADR 职责；记录纳入版本控制。

记录可按 `<lifecycle>/<class>/<record>.md` 组织；分类按需要启用，小项目可省略分类层。生命周期、分类、记录身份与归档状态分别判断，不由目录深度推断决策内容。布局说明可以放在 Notes README，导航可用现有目录和搜索；不强制建立集中式 `INDEX.md`。

## 所有权

- 架构地图拥有系统组合、主要运行路径、扩展点和阅读路线。
- 子系统参考拥有当前类型、语义、边界和验证。
- 包 README 拥有包消费者契约、配置、公开接口、限制、扩展点、用户/模型可见行为和包级验证。
- Agent Notes 拥有提案、替代方案、决策理由和后果；当前事实文档通过链接引用理由，不复制正文。
- postmortem 拥有事故因果链和预防。
- 规范拥有可执行的审查规则、理由和验证证据。
- 指南或 cookbook 拥有面向结果的有序操作步骤。
- 生成参考由源代码和生成器拥有，禁止手工编辑生成区域。
- 索引只导航，不复制事实。

## 内容边界

下列信息按实际主题取用，可并入已有页面或链接到 owner，不要求复制固定模板：

- subsystem：职责和边界、当前运行路径、状态与失败恢复、兼容性及限制、源码位置和验证；不替代高层架构地图，也无需为不存在的状态机补章节。
- 规范：范围、规则、理由、失败模式、验证和例外；采纳依据与验证方式分别记录，见 [规范形成与采纳](standards-governance.md)。
- postmortem 或项目已有经验记录：现象与影响、根因、修复、如何更早发现和证据；只有项目定义了 Lessons 层时才使用该名称，提升为规范需另作判断。
- 契约索引：机器可读 source、生成产物、generator/check 和语义 owner。Schema 不能替代权限、生命周期、顺序、错误及兼容性语义的说明；索引只链接这些 owner。

## 状态

当前文档使用现在时态；设计记录保留项目的采纳、交付和冻结语义，没有约定时使用 `proposed`、`implemented`、`rejected`。`archived/` 表示退出当前维护，可保留原始决策状态并另记归档信息，不要求目录名与 `Status` 字符串完全相同。生成物标注 source/generator；候选事实标记来源和置信度，不把已采纳方案等同于已实现行为。
