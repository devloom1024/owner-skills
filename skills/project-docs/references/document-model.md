# 文档模型

按文档职责和主题所有者组织项目文档。目录表达职责，文件表达事实或理由，索引负责导航。

## 推荐入口

```text
docs/
├── AGENTS.md
├── README.md
├── architecture.md
├── subsystems/
├── standards/       # 项目需要跨模块规范时启用
├── agent-notes/     # 项目采用 Agent Note 生命周期时启用
├── postmortem/      # 项目需要事故复盘时启用
├── guides/          # 存在可重复操作流程时启用
└── contracts/       # 存在机器可读契约时启用
```

这是一组职责模型，不是必须完整创建的空目录树。已有项目按实际内容和事实所有者判断是否保留。

## 所有权

- 架构地图拥有系统组合和阅读路线。
- 子系统参考拥有当前类型、语义、边界和验证。
- 包 README 拥有包消费者契约、配置、限制和扩展点。
- 设计记录拥有提案、替代方案、决策理由和后果。
- postmortem 拥有事故因果链和预防。
- 规范拥有可执行的审查规则和证据。
- 生成参考由源代码和生成器拥有。
- 索引只导航，不复制事实。

## 状态

当前文档使用现在时态；设计文档遵循项目已有 ADR/决策生命周期，没有约定时才参考 `proposed`、`implemented`、`rejected`、`archived`。生成物标注 source/generator；候选事实标记来源和置信度，不把采纳的方案等同于已实现行为。
