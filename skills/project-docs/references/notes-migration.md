# 决策记录迁移

按本次明确请求的范围规划、执行或审计一次性迁移；规划和审计保持只读。目标布局、所有权与状态采用 [文档模型](document-model.md)。

## 范围与发现

1. 从项目指令、文档导航、源码引用和实际内容定位现有记录，不预设来源目录；已符合目标模型的记录原位保留。递归搜索已确认的根并包含隐藏目录，排除无关缓存、依赖和第三方仓库。
2. 依据 [指令层级](instruction-hierarchy.md) 核对源/目标规则及冻结限制；冲突时暂停受影响项，不以复制记录绕过限制。
3. 确认每个决定的当前 owner、有效范围、采纳与交付依据、替代关系、独有理由，以及翻译、配对元数据、附件和活跃入链。路径与正文冲突时列为待确认，不批量猜测状态。
4. 在本次计划中列出来源/目标、保留/移动/整合/归档动作、理由、关联文件和验证方式。按规模分批，保留可恢复的基线或备份 manifest，无需新增永久治理配置。

## 逐项判断

| 记录情况 | 动作与内容要求 |
|---|---|
| 决定仍有效，理由仍指导开发 | 按实际映射保留或移动，保持唯一当前 owner；保留决定、备选方案、代价和必要验证。 |
| 提案仍在推进 | 保留真实状态，按需调整位置；已采纳但未交付不标成 `implemented`。 |
| 部分被替代 | 保留仍有效的范围，与新记录明确互补或替代关系；不能整体退出当前维护。 |
| 已完全被替代，或只剩历史价值 | 确保当前 owner 已承接仍适用的约束、独有理由和验证缺口，再归档有历史价值的记录。 |
| 提案已停止推进 | 明确否决或撤回结论，保留有意义的理由；不伪装成已实现记录再归档。 |
| 存在重复记录 | 将独有内容整合到选定 owner，其余记录按历史价值和项目规则处理；删除仍须在授权范围内，不依赖 Git 历史作为唯一理由来源。 |

不按文件年龄、字数或目录名称决定归档。混写的当前事实与决策理由按文档模型拆分所有权。

## 执行与收敛

- 保留稳定编号、首次提出日期和项目状态词汇；纯路径迁移不改变采纳或交付结论。需要状态转换或决策变更的项单独说明依据，不以迁移时间覆盖原日期。
- 按已识别的关联集合移动，保留共享附件的其他引用；同步活跃入链、可编辑记录的相对链接、现有导航和路径映射。
- 同步 AGENTS 路由和验证配置，使目标位置可发现、可检查；源路径局部规则按适用范围适配，不原样搬用。
- 按项目封存流程完成允许的移动和元数据更新；冻结正文及其出链不自动改写，受限项保留原位并报告。配置调整不得削弱冻结或完整性检查。
- 停用被替代的活跃入口；需要链接兼容时只留简短跳转，不留可独立更新的重复正文。

## 验收与结束

- 范围内每条记录均有结果，当前 owner 唯一，仍有效的决定与独有理由未丢失。
- 导航和映射可到达当前 owner，历史引用用途明确；迁出入口不再引导新建或双写。
- 关联集合、身份和状态语义保持完整；适用的链接、完整性与封存检查覆盖本次变更，包括归档。未验证命令、外部链接限制和未完成批次均已报告。

没有待迁移项时说明依据并结束；完成后回归日常维护，不在后续普通任务中自动重启或重复提示。
