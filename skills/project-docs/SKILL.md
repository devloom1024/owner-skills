# 项目文档

负责文档的职责、放置、当前事实、导航和验证。审计或规划请求保持只读；明确要求建立、更新、整理或修复文档时，在约定范围内执行，不重复索要编辑授权。超出范围的删除或大规模迁移另行确认。

只检查同步遗漏时选择 `project-change-sync`；设计理由可配合 `project-design-notes`，变更正确性可配合 `project-code-review`。辅助 Skill 未安装时依据项目现有规则完成当前任务，不因此阻塞。

## 先读什么

1. 根目录和变更路径祖先的 `AGENTS.md`；
2. [文档模型](references/document-model.md)；
3. [指令层级](references/instruction-hierarchy.md)；
4. [事实验证](references/fact-check.md)；
5. 项目相关文档及 Notes 的规则、导航和验证脚本。

按任务补充读取，不要求普通编辑加载全部资料：

- 初始化新项目文档或为缺少文档的项目补建基线时，读取 [文档初始化](references/bootstrap.md)。
- 仅在用户明确请求规划、执行或审计决策记录迁移时，读取 [决策记录迁移](references/notes-migration.md)。安装、初始化、普通编辑和布局差异都不触发此流程。
- 提炼、审计或维护开发规范，或考虑将缺陷经验提升为规范时，读取 [规范形成与采纳](references/standards-governance.md)。
- 建立或调整指令文件时，参考 [根 AGENTS 模板](templates/root-AGENTS.md) 与 [文档 AGENTS 模板](templates/docs-AGENTS.md)，先替换路径并删去不适用的职责和门禁；不覆盖合理的已有规则。

## 工作流

1. 固定任务和范围：初始化、审计、单页更新，或明确要求的目录重组与迁移。
2. 识别读者、文档主要职责和事实所有者；一份文档只拥有一个主要职责。
3. 先读事实来源：源码、配置、测试、生成器、包 manifest 和当前决策记录。
4. 按文档模型选择文档位置和所有者。
5. 当前事实只写已经有证据的行为；规范分别记录采纳依据与验证方式，不把观察到的惯例直接写成强制规则。长期取舍先核实既有决策 owner，不复制正文，也不为普通修订另建提案。
6. 编辑模式下更新受影响的入口、索引、链接、生成器说明和验证命令；审计模式只报告对应缺口。
7. 记录来源、置信度、未验证命令和仍需人工决定的语义。
8. 目录重组和批量移动按任务规模准备路径映射、恢复基线和分批验证；普通单页编辑直接完成修改并验证。

## 文档更新

代码变化影响职责、接口、状态、失败、兼容性、配置、生成区域、公开文案或操作流程时，在同一变更中更新对应所有者，或记录 `not-needed` / `review-required` 的证据。先更新事实源，再更新派生文档。

## 输出

按任务规模使用 [报告格式](references/report-format.md)。普通编辑说明修改、来源、验证和未决事项即可；初始化补充最小入口、事实内容、候选项及初始所有权映射；规范工作分开报告采纳依据和验证证据；结构调整再补充路径映射、有效指令和验证范围。
