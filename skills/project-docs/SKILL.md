# 项目文档

负责文档的职责、放置、当前事实和验证。设计理由交给 `project-design-notes`，代码变化影响交给 `project-change-sync`。

## 工作流

1. 阅读根目录及变更路径祖先的 `AGENTS.md`。
2. 读取 [文档模型](references/document-model.md) 和 [事实验证](references/fact-check.md)。
3. 判断任务是 bootstrap、审计、重构还是单页更新。
4. 为每份文档指定一个主要职责和一个事实所有者。
5. 根据代码、测试、配置、生成器和已有文档写入当前事实；不把推断写成已确认行为。
6. 更新文档入口、索引、链接和验证命令。
7. 输出范围、所有权、证据、未验证事项和建议批次。

## 文档职责

- `architecture.md`：系统地图和阅读路径。
- `subsystems/`：当前职责、边界、状态、运行路径、失败、限制和验证。
- `standards/`：规范性规则及其证据。
- `agent-notes/`：持久化设计理由和决策记录。
- `lessons/`：真实缺陷、根因和预防。
- `guides/`：达成结果的有序步骤。
- `contracts/`：机器可读契约、生成器和语义所有者索引。
- 包本地 README：包用途、接口、配置、限制和验证。

## 安全边界

默认只读。迁移需要明确授权、备份 manifest、逐文件映射和批次验证。项目现有的合理目录和文档可以保留，不因模板而重写。
