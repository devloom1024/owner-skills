# CI 不稳定诊断

## 诊断记录

- 失败概率、首次和最近日志：
- worker/job/process 拓扑：
- 共享资源和 owner：
- 原子分配和 readiness：
- 同步信号和 timeout budget：
- cleanup、退出和 quiescence：
- 平台差异：
- 最小复现和负例：
- 根因、修复方向和验证：

诊断-only 请求保持只读。优先修复资源所有权和同步缺陷，不用 sleep、重试或全局串行化掩盖问题。

## Timeout 判断

- 先对照 CI lane 原有预算和失败日志，区分预算回退、合法操作变慢、无界等待和清理缺陷。
- 恢复误缩小的预算，或按测量设置明确条件的有界等待时，记录依据、上界、失败诊断与 setup/teardown 余量。
- timeout 只限制等待时长，不构成 readiness 信号；用事件或条件确认完成，超时后仍需清理资源。
- 修复后覆盖真实 CI 拓扑；重复通过只能补充稳定性证据，不能取代同步正确性。
