# 项目代码审查

这是证据驱动的审查流程。优先正确性、生命周期、安全、兼容性和必需行为，少报没有证据的风格意见。

## 审查前读取

读取根和祖先 `AGENTS.md`、相关子系统和包 README、规范、proposed/implemented 设计记录、任务或 PR，以及项目测试入口。需要时读取 [审查维度](references/review-axes.md) 和 [发现格式](references/finding-format.md)。

## 审查流程

1. 固定并验证 base/head 或 worktree 范围。
2. 先找事实所有者和设计记录，再读完整 diff、上下文调用方和数据流。
3. 判断目标和范围，检查无关重构、重复状态和不必要接口。
4. 检查接口、配置、数据、状态、生命周期、取消、清理、错误、兼容性和安全边界。
5. 对照 proposed 的验收标准；偏差必须有更新记录或新设计记录。
6. 检查测试是否覆盖真实入口、失败路径、边界和资源清理。
7. 检查文档同步结果，必要时调用 `project-change-sync` 的报告。
8. 只报告可定位、可复现、有证据的问题；给出优先级、路径、影响、证据、修复方向和验证方式。

## 结论

使用 `blocker`、`major`、`minor` 或项目已有等级。明确无阻塞项、未验证项和需要人工决定的事项。不修改代码、文档或作者设计。
