# Adaptive Navigation — 导航随空间变化，不改变 IA

## 首选规则

| 场景 | 建议方式 | 禁止的常见误区 |
|---|---|---|
| 桌面持续访问多个顶层区域 | Sidebar / Rail | 每个页面布局都换导航位置 |
| 小屏顶层入口约 3–5 个 | Bottom Tabs（宿主和任务适合时） | 导航项超过可读宽度仍全部挤在 Tab Bar |
| 移动层级较深 | Push / Back / Breadcrumb 等价路径 | 返回无法预测、跳出整个任务 |
| 中等宽度可同时展示两个层级 | Split View | 明明空间不足却强制两栏 |
| 只在局部内容切换 | Tabs | 用 Tabs 模拟整个应用的多级导航 |

## 规则

1. 导航名称、分组、当前选中状态不因平台改变。
2. 可切换导航承载的是同一信息架构：桌面 Sidebar ↔ 移动入口页 + Back 等价。
3. 窄桌面窗口优先折叠 Sidebar；是否采用底部 Tab 应根据**产品的顶层导航任务**决定，而不是只看尺寸。
4. 保存当前列表筛选、滚动位置和详情返回上下文，避免用户来回导航丢失工作。
5. 面板关闭与页面退出不是一件事，必须区分 UI 反馈。
