# Form — Shared Pattern

## 1. Purpose

用于**创建或修改结构化数据**，用户需要理解字段、校验、保存时机和离开后的后果。小而即时的单项开关不应套成完整表单流程。

## 2. Anatomy

1. **Form Title + Purpose**：明确新增/编辑的对象类型。
2. **Field Groups**：按逻辑拆分，不按数据库字段随机顺序排列。
3. **Field**：持久可见 Label、输入控件、帮助说明、可选/必填标识、行内错误。
4. **Actions**：提交/保存为主，取消为次；操作位置稳定。
5. **Global Error / Save State**：网络失败、服务端冲突、待保存状态可辨。
6. **Leave Guard**：未保存内容离开时按风险确认、自动草稿或恢复机制。

## 3. 必须统一的行为

- 清楚区分 **保存草稿**、**提交**、**立即生效**，不能同一按钮文案代表不同后果。
- 校验以可理解、可恢复为原则：字段级消息紧邻字段；提交失败后焦点移动到错误摘要/首个错误字段（按复杂度选择）。
- 必填字段清晰提示；对全部必填的短表单，可通过页首说明替代每行星号，但要一致。
- 同一字段不能在 Desktop 使用密码强度说明、Mobile 完全不显示相关条件。
- 网络失败保留所有用户输入；服务器冲突需要解释覆盖/合并策略，不能静默丢弃。
- 保存成功后应说明留在编辑页还是返回详情，且各平台符合相同业务结果。

## 4. 表单分组与布局

- 同一语义字段始终使用同一标签、格式、校验规则、单位。
- 字段排列以任务步骤而非表格列顺序决定；长文本、地址、多语言输入需预留增长空间。
- 高风险提交前可用总结确认；简单低风险表单不必每次多一步确认。

## 5. Do / Don't

✅ 明确错误“名称不能为空”，保留输入和保存上下文。  
❌ 只弹出“失败”Toast 后清空页面。  
✅ 一个表单中保存与取消位置一致。  
❌ 仅用 placeholder 说明字段含义，输入后说明消失。
