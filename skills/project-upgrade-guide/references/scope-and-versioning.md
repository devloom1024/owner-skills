# 范围和版本

只有对外部消费者、公开接口、配置、协议、持久化数据或用户流程造成破坏、需要采取迁移动作的变化才需要升级指南。兼容性新增和纯内部重构通常只需常规文档或变更记录。读取项目实际版本来源和发布规则，不猜版本号。

优先使用项目已有格式；默认模板在文件开头使用 YAML frontmatter，含 `kind: upgrade-guide` 和一句说明破坏的 surface，正文以 `Change`/`Migration` 说明变化及迁移。只遵守项目实际设定的字数和章节门禁，复杂理由链接到已有设计记录。

明确目录版本代表来源版本还是目标版本；不要把某个项目的 `v<version>/<item>/guide.md` 模型当作通用规则。发布前随代码变化维护草案，发布后按项目的冻结、勘误和后续迁移规则处理。没有可确认的版本时标为待确认，不因为模板要求而制造版本号；这不阻止先写有证据的变化与迁移内容。
