# 项目升级指南

升级指南告诉外部消费者从一个版本迁移到下一个版本。它不记录内部实现历史，也不把未确认的计划写成迁移步骤。

## 范围判断

检查 CLI 命令/参数、配置和环境变量、公开 API/SDK、协议和消息、持久化数据、包名称/入口、默认值、用户操作流程和兼容性。所有消费者在同一变更中更新且没有外部可见影响的 pre-stable 内部 API 通常不需要指南，但要在报告中说明证据。

## 工作流

1. 阅读项目版本来源、发布规则、兼容性记录、设计记录和完整 diff；
2. 确定受影响消费者、版本来源、旧行为、新行为、迁移步骤、兼容期和失败处理；
3. 使用项目既有指南位置和模板；没有约定时选择合适目录，并明确 `from`/`to` 的方向，不能猜测发布版本；
4. 链接 canonical implementation、设计、测试和验证命令；
5. 如果项目有双语规则，同一变更更新配对文件和 pairing metadata；
6. 按项目实际规则校验版本、链接、frontmatter 和章节；迁移命令只在获准的隔离环境验证，不直接作用于生产数据；
7. 记录未验证环境和负责确认的人。

## 维护规则

优先遵循项目对来源版本、目标版本、发布冻结、历史纠错和多版本迁移的约定。没有约定时明确旧/新行为与适用版本，迁移说明随破坏性变化准备，不强加特定目录模型。未发布的变化被撤销时更新或移除对应草案；已发布指南不自动删除，保留历史并按项目方式补充勘误。

## 输出

读取 [范围和版本](references/scope-and-versioning.md) 和 [升级指南模板](templates/upgrade-guide.md)。判断或审查请求只读；明确要求编写或更新指南时执行文档编辑。指南编写不授权发布版本、运行生产数据迁移或修改外部环境。
