# 项目升级指南

升级指南告诉外部消费者从一个版本迁移到下一个版本。它不记录内部实现历史，也不把未确认的计划写成迁移步骤。

## 范围判断

检查 CLI 命令/参数、配置和环境变量、公开 API/SDK、协议和消息、持久化数据、包名称/入口、默认值、用户操作流程和兼容性。所有消费者在同一变更中更新且没有外部可见影响的 pre-stable 内部 API 通常不需要指南，但要在报告中说明证据。

## 工作流

1. 阅读项目版本来源、发布规则、兼容性记录、设计记录和完整 diff；
2. 确定受影响消费者、版本来源、旧行为、新行为、迁移步骤、兼容期和失败处理；
3. 在项目规定位置创建或更新 `v<version>/<item>/guide.md`；
4. 链接 canonical implementation、设计、测试和验证命令；
5. 如果项目有双语规则，同一变更更新配对文件和 pairing metadata；
6. 校验版本、链接、frontmatter、字数/章节门禁和迁移命令；
7. 记录未验证环境和负责确认的人。

## 维护规则

当前版本目录描述从该版本到下一版本的变化；版本提升后旧目录冻结，新变化进入新版本目录。变化被撤销时删除对应指南。一个指南不跨越多个发布版本。

## 输出

读取 [范围和版本](references/scope-and-versioning.md) 和 [升级指南模板](templates/upgrade-guide.md)。默认只读规划，发布版本和迁移策略遵守项目自身规则。

## 评估

正常、边界和失败/不确定场景见 [evals/evals.json](evals/evals.json)，输入 fixture 位于 `evals/files/`。
