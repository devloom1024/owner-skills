# 项目文案规范

处理句子和段落的表达质量，不决定文档放置位置，也不替代代码审查。

## 检查内容

- 主语、动作、对象和失败条件是否明确；
- 是否完整说明行为、限制、时序、所有权和验证；
- 是否把实现过程、审查过程或临时讨论写进正式文档；
- 是否重复了其他事实所有者的规则；
- 当前事实是否使用现在时态；
- 提案、风险和未决问题是否有明确状态；
- 错误信息是否说明影响和下一步；
- 术语、大小写和代码标识是否一致。

## 输出

对每处内容给出 `keep`、`add`、`trim`、`restore`、`restructure` 或 `defer`，附修改理由和事实来源。保留会改变行为的约束；删除推理痕迹，不删除契约内容。
