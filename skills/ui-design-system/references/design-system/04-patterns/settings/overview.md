# Settings — 共享 Pattern

## 1. 用途

用于偏好、账号、安全、通知、外观等**较稳定的用户配置**。不适合直接承载任务型编辑工作流（复杂编辑请使用 Form Pattern）。

## 2. 结构（跨端不变）

1. **Settings Navigation / Categories**：按用户认知分组，分组名称稳定。
2. **Page/Section Title**：表达当前类别，必要时有一行说明。
3. **Settings Group**：一组相互关联的设置项；按场景优先级排序。
4. **Settings Row**：标签、可选描述、当前值或控件、状态反馈。
5. **Danger Zone**：注销账号、清空全部数据等高风险行为，独立于日常偏好。
6. **Search（可选）**：设置项很多时提供跨分类搜索，搜索结果保留分类上下文。

## 3. 默认规范

- 常规行最小高度：Compact 48px；Comfortable/Touch 56px；包含多行说明时高度随内容增长。
- 主内容阅读宽度不超过 720px；超过宽度不强制让开关位于屏幕最右边。
- 一行一个主要设置决策；标签与控制关系明确；组间距优先 `space.6/8`。
- 开关用于**立即生效**布尔设置；需确认/保存的字段用 Form 流程，不混淆“开关已生效”和“待保存”。
- 值改变成功/失败必须有反馈；失败应恢复到真实状态或明确“待重试”。
- 改变全局语言、主题、密度等需要预期中的全局更新，不应无提示打断用户当前任务。

## 4. 行类型（选择标准）

| 类型 | 内容 | 适用情况 |
|---|---|---|
| Switch Row | 标签/说明 + Switch | 即时、可逆布尔偏好 |
| Value Row | 标签 + 当前值 + 进入详情 | 多选、复杂值、移动端需要独立选择页 |
| Inline Control Row | 标签 + Select/Radio/Slider | 选项少、空间充足且含义清晰 |
| Action Row | 明确动词 + 反馈 | 重置缓存、导出、检查更新 |
| Danger Row | 破坏性动词 + 后果说明 | 删除账号、永久清理 |

## 5. 共享交互及状态

- Immediate-save：操作立即开始，进行中防重复，失败恢复并提示；成功通常不需每次弹出模态。
- Explicit-save：只有明确设计为设置表单时使用保存/取消，避免将两种模型混在一个分组。
- 权限限制/策略托管项：清晰显示来源和不可编辑原因，不只是灰掉控件。
- 设置项跳转二级内容后保留来源、当前类别及滚动上下文。
- Loading/Empty/Error 状态不得把所有分组布局替换成无法恢复的空白。

## 6. 应该 / 不应该

✅ 分组采用统一行风格；“危险操作”独立呈现。  
❌ 同一类设置一会卡片、一会裸表单、一会用彩色大按钮，而无任务差异。  
✅ 标签简洁，说明可以换行，控制保持对齐。  
❌ 用 placeholder 充当设置名称，或用仅图标暗示设置含义。
