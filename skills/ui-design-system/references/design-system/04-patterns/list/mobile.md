# List — 移动端

> 先遵守 [Shared List](overview.md)。

## 布局

- **优先单列摘要列表**：一条显示主识别字段 + 1–3 个最重要信息（例如状态、时间、金额）；更多详细字段进入 Detail。
- 搜索入口应明显；筛选项较多可用 Sheet 或专门筛选页，当前活动筛选条件需可见且可清除。
- 列表项可使用行或分组卡片，但整个列表坚持同一密度；不要在一个列表混合 6 种不相关卡片样式。
- 列表项触摸目标推荐 ≥44px；状态与更多操作不能挤占主标题的有效宽度。
- 大量对象可使用分段加载/无限滚动，但要考虑返回定位、加载反馈和到达列表末端的方式。

## 交互

- 点击摘要进入 Detail；更多操作通过可见的三点/操作按钮进入；Swipe/Long Press 可辅助但不能独占动作。
- 多选使用明确“选择”模式，进入后出现清晰数量与批量动作；防止轻触整行时含义突然改变。
- 从详情返回保持搜索词、筛选条件、当前位置；从底层数据更新回来可在原位置标识更新。
- 排序选项过多时使用简单操作列表而不是压缩成顶部 6 个小 Tab。

## 异常与例外

复杂财务数据/必须横向比较的表格，可提供专用可滚动表格模式，但要清楚标示可横向滚动且支持可访问表头；不应把整张表强行改成无法比较的卡片。

## 验收

320/390/430px，筛选展开/关闭、软键盘搜索、多选、长文案、离线错误和返回上下文。
