# Detail — 共享 Pattern

## 1. 用途

用于展示和操作一个**可被识别的单独对象**（如某个项目、会话、订单、用户、文件），支持阅读、查看历史、编辑入口和关联信息。

## 2. 结构

1. **Identity Header**：标题/名称、关键状态、主要标识，可选返回与面包屑。
2. **Primary Actions**：与当前对象有关的 1–2 个核心动作；危险操作适度隔离。
3. **Primary Content**：最主要的详情，按信息分组而不是随机卡片。
4. **Supporting Sections**：活动记录、附件、关联对象、元数据；用固定顺序。
5. **Optional Inspector**：辅助上下文、关系、历史；允许折叠但不能成为唯一重要信息载体。
6. **Feedback & States**：Loading、Not Found、Permission Denied、Offline、Stale Data、Error。

## 3. 共享行为

- Detail 必须明确“我正在查看哪个对象”；对象标题和主状态在关键操作前可辨。
- 更新/编辑通常进入 Form 或行内明确编辑模式；只读内容与可编辑内容必须明显区分。
- 返回列表后尽量恢复原筛选与列表位置；从外部深链进入时提供合理返回目标。
- 对象不存在、无权限和临时加载失败必须区分；不可统一用空白页。
- 所有对象操作（导出、复制、归档、删除等）在不同平台后果一致、词汇一致。
- 动作成功可以就地更新；危险且不可撤销时需要合适的确认/后果描述。

## 4. 阅读与信息层级

- 使用 Section Title 与分组，不把每个字段都做成独立突出卡片。
- 标签与值对应清晰；关键状态尽量靠近对象标题，时间与来源属于辅助信息。
- 很长的正文可使用可读宽度（建议 720px）或与内容任务相配的宽度；画布/日志等可采用全宽。

## 5. 应该 / 不应该

✅ 主标题能确定对象，主动作集中、稳定。  
❌ 一个详情页的全部功能都隐藏在不明显的三点菜单中。  
✅ 未找到对象时告知原因并提供回到集合的路径。  
❌ 桌面端 能看到完整状态，移动端 只显示标题而丢失关键风险提示。
