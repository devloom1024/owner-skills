# Detail — 桌面端

> 先遵守 [Shared Detail](overview.md)。

## 布局

- 主标题与主要动作在 Page Header；内容区采用主列 + **可选**右侧 Inspector。
- 文本类详情主列建议 max 880px；其中长篇正文局部可使用 720px 可读宽，不强制所有模块同宽。
- Inspector 作为辅助信息而非必需信息的唯一容器，推荐在空间不足时先折叠。
- 关联列表与活动历史要有稳定的分组与顺序；如果内容过多，可使用页内 Tabs/Anchor 导航。
- 不因桌面屏幕宽就默认三栏；多栏必须具有实际的比较/并行操作收益。

## 交互

- 对象主操作建议位于标题附近或统一工具栏；二级动作放“更多”，危险项分组隔离。
- Hover/右键可以提供快速操作，但通过可见菜单/键盘仍可执行。
- 子面板、预览、日志如具独立滚动，必须清楚焦点归属和滚动边界。
- 键盘快捷键可用于编辑/复制/返回，但不应与输入框或系统行为冲突。

## 窄桌面窗口

先关闭辅助 Inspector，再折叠页内 Navigation；主内容转为单列，但保留桌面键盘、菜单与窗口行为。不要只因为 500px 宽就自动增加底部 Tab。

## 验收

查看对象 → 编辑 → 取消/保存 → 返回列表；同时测试窄窗、长文本、隐藏 Inspector 后的内容可达性。
