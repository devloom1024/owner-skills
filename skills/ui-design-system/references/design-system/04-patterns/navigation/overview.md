# Navigation — 共享 Pattern

## 1. 用途

在应用顶层区域、同级类别与详情层级之间切换，同时提供**我在哪、从哪里来、怎么返回**的可预测体验。

## 2. 结构

1. **Primary Destinations**：数量稳定、术语一致的顶层目标。
2. **Current Location**：选中态、页标题、必要的父级导航。
3. **Secondary Navigation**：某区域内子类别（如 Settings 类别或页内 Tabs）。
4. **Back / History**：从对象列表进入详情、从 Settings 类别进入二级选项的返回路径。
5. **Utilities**：全局搜索、帮助、用户菜单等，不应该混为主导航同级项。

## 3. 共享规则

- 一项导航名称只代表一种稳定目的地；不同设备不应改变目的地的业务含义。
- 层级最多保持用户能理解的深度：能平铺就平铺，过深时提供上下文与可返回路径。
- Top-level destinations 与 contextual tabs 不得混为一个导航层级；Tabs 只切换当前上下文视图。
- 用户在不同目的地之间切换时，应有明确的“返回当前任务”路径；关键筛选与草稿状态能恢复。
- 选中态应有文字、视觉标识及可访问语义，不仅靠品牌色。
- 无权限目的地的隐藏/禁用策略一致，并与安全/权限产品逻辑协同。

## 4. 导航选择规则

| IA / 场景 | 适合的模式 |
|---|---|
| 3–5 个高频顶层区，手机产品 | Bottom Tabs 可选 |
| 多个常用顶层区，桌面业务工具 | Sidebar / Navigation Rail |
| 当前页不同数据视图 | Tabs |
| 深层记录阅读与返回 | Stack Back / Breadcrumb / 上下文标题 |
| 局部筛选/排序 | 工具栏，不属于导航 |

## 5. 应该 / 不应该

✅ Sidebar 和底栏指向同一组顶层区域，名称一致。  
❌ 在桌面“工作区”对应移动“任务”，却实际打开不同内容。  
✅ 详情返回后保留列表筛选/位置。  
❌ 每次切换一级菜单就把未保存工作清空。
