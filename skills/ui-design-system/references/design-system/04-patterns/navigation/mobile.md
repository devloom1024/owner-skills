# Navigation — 移动端

> 先遵守 [Shared Navigation](overview.md)。

## 布局

- **顶层高频目标约 3–5 个**时可采用 Bottom Tabs；高于可读数量则合并为层级入口，而不是挤成微小图标。
- 深层导航采用 Push/Back 页面栈；进入详情/设置子项时，按业务需要保留或暂时隐藏底部主导航，策略必须全产品一致。
- 导航条需要考虑 safe area；内容滚动不应被底栏覆盖。
- 少量当前页同级视图可以用 Tabs/Segmented，但不得同时叠三层底栏/顶栏/横向 Tab。

## 交互

- 系统/手势返回、可见 Back 入口和业务导航需保持逻辑一致；切换主 Tab 与返回子页面的行为应可预测。
- 长按 Tab 可提供快捷功能但不是唯一入口；主导航选中状态持续可见。
- 从外部通知/链接打开深层页面时，提供稳定的上级目的地，并可回到对应 Tab。
- 切换主导航后若草稿或筛选未保存，遵循共有的状态保留/确认规则。

## 例外

简洁阅读型 PWA 只有一两个顶层目的地时不必强制底栏；移动浏览器宽度增加不自动切成桌面 IA。

## 验收

390/320px、横竖屏、系统返回、深链、软键盘、Bottom Tab 安全区、长导航标签及辅助技术。
