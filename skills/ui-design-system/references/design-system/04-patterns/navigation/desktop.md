# Navigation — 桌面端

> 先遵守 [Shared Navigation](overview.md)。

## 布局

- 应用主导航首选 Sidebar 或 Rail；命名、图标与选中态跨页面稳定。
- 若有二级区域，可用 Sidebar 分组、局部 Tabs 或子导航，但不要多重横向 Tab 堆叠导致层级无法识别。
- 容器不足时优先将 Sidebar 折叠为 Rail、抽屉或入口菜单，主内容保持可用；折叠入口必须明显。
- 新建动作、全局搜索、帮助等 Utilities 与主导航分层，防止与同级目标混淆。

## Interaction / 交互

- 导航项可通过 Tab 和 Enter/Space 等合理语义激活，当前页有清晰 focus 和 selected 区别。
- 鼠标 Hover 展示提示文本可以辅助 Rail，但 Rail 中无文字图标必须具有可访问名称与键盘可发现的含义。
- 可使用窗口系统 Back/Forward、快捷键打开页面，但不可覆盖系统常见组合键。
- 拖动调整 Sidebar 宽度如果存在，需有下限、上限和键盘替代方式。

## 窄窗行为

420px 桌面窗口通常保留抽屉/折叠导航，而不是无条件改成 iOS 底栏；若产品本身就是底栏优先 IA，可例外，必须有文档理由。

## 验收

键盘导航所有一级/二级入口，深链进入，改变窗口宽度后当前导航状态不丢失。
