# Exceptions & Versioning — 规范例外和版本治理

## Exceptions / 例外不是坏事，未记录的例外才会导致失控

允许偏离的场景：密集代码编辑器、复杂看板、极长表格、原生系统必须遵守的特定行为、已验证的业务转化问题。不能以“这个更好看”作为唯一理由。

## Exceptions / 例外记录模板

| 字段 | 必填说明 |
|---|---|
| ID / 提出日期 | 可追踪 |
| 所属页面/模式 | 具体路径和 Pattern |
| 偏离内容 | Token、导航方式、交互规则 |
| 原因与候选方案 | 为什么现有规范不适合 |
| 用户影响和风险 | 可访问性/学习成本/跨端差异 |
| 负责人/审批 | 项目可自行设责任人 |
| 到期/复审条件 | 什么时候合并进规范或移除 |

## 版本说明

- `MAJOR`：改变共享设计语言或 Pattern 基础行为，可能要求多个项目同步调整。
- `MINOR`：新增 Pattern、平台规则或向后兼容的 Token 语义。
- `PATCH`：错别字、链接、阐释、不会改变实现结果的规则澄清。

任何变更需要：更新相关规范、仓库根 README/CHANGELOG、跨文件 Token 引用、示例和 AI 路径。建议以规范版本号标注每个项目的实际采用版本，避免多个项目“都是 v1.1”却含不同规则。
