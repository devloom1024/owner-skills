# Review Checklist — UI 交付验收清单

> 建议每个 PR 或 AI 生成页面合入前逐项自检；存在不适用项写 N/A 与原因。

## A. 结构 / Pattern

- [ ] 页面选择了正确 Pattern，阅读 `overview.md` 及相关桌面端/移动端文件。
- [ ] 页面标题、分区、内容和主要操作的层级清晰且同类页面一致。
- [ ] 主要任务与关键入口未因布局变更而消失；返回路径可预测。
- [ ] 页面级空间、分组空间、组件内部空间没有重复控制。

## B. 视觉 Token

- [ ] 字号、行高、字重来自语义 Typography。
- [ ] 间距来自 4px 网格；无未经批准的任意值。
- [ ] 控件、卡片和浮层圆角按语义统一。
- [ ] 背景、文字、边框和状态采用语义颜色；浅色/深色都可辨认。
- [ ] 图标风格与实际命中范围一致；状态不只靠图标或颜色。

## C. 响应式与输入

- [ ] 窄桌面窗口不会被错误当成手机系统；触控宽屏也不会错误降为鼠标密度。
- [ ] 验证窄（320–420）、中（768–900）、宽（1024–1440）容器；没有无法解释的横向溢出。
- [ ] 主要操作可通过鼠标、键盘、触摸访问，关键功能不依赖悬停、右键或长按。
- [ ] 软键盘、安全区域、窗口调整和 200% 缩放不会遮挡主要操作。

## D. 状态与无障碍

- [ ] Loading/Empty/Error/Success/Disabled/Offline-Sync 及适用 Pattern 扩展状态有清楚反馈和恢复路径。
- [ ] 焦点顺序正确且可见；Dialog/Sheet 焦点进入和恢复正确。
- [ ] 文字与控件对比度达到适用目标；触摸目标足够大。
- [ ] 危险操作的动词、后果和确认/撤销方式合理。
- [ ] 减少动画偏好、键盘导航和长文案已验证。

## E. 证据

- [ ] 记录测试环境：平台、浏览器/宿主、视口/容器宽度、输入方式、主题和字号。
- [ ] 200% 检查明确使用浏览器缩放、系统大字体或辅助技术中的哪一种。
- [ ] 对比度使用可复核测量工具或计算结果；触摸目标按实际命中区域测量。
- [ ] 键盘与屏幕阅读器检查至少一个关键任务路径；未覆盖项写明原因和风险。

## F. 交付物

- [ ] 例外已按记录模板写明原因、影响范围、负责人和复审条件。
- [ ] 适配说明包含测试设备、容器和输入方式，而非只写“手机、桌面都可以”。
- [ ] 未重复建立既有 shadcn/ui 同功能组件或第二套页面 Pattern。

## 最小评审报告模板

| 字段 | 填写 |
|---|---|
| Pattern | 例如 `settings` |
| 测试场景 | 390 touch / 420 mouse+keyboard / 820 touch / 1440 mouse |
| 视觉验证 | Light/Dark、Typography/Spacing/Radius |
| 交互验证 | Focus、Loading、Error、Back、Resize |
| 已知例外 | 约束、原因、风险、回归方式 |
