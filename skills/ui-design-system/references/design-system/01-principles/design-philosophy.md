# 设计理念（Design Philosophy）

## 目标

建立可以量化与检查的统一 UI 语言；避免“单页好看，产品不统一”。参考 Apple HIG 的平台熟悉感与 Fluent 2 的生产力密度、清晰层级；**不拼贴品牌风格**。

## 七项原则

1. **Consistency / 一致性**：相同含义使用同一布局关系、组件语义、Token、反馈；新样式要先解释为何现有规范不适用。
2. **Clarity / 清晰**：信息结构优先于视觉装饰；一级标题、分组、主体、次要内容必须明显区别。
3. **Hierarchy / 层级**：页面标题 → 分组 → 项 → 辅助描述；操作权限和风险等级可被迅速识别。
4. **Progressive Disclosure / 渐进披露**：高级参数按需出现，不把全部设置压到第一屏；重要设置要可发现、可返回。
5. **Platform Appropriateness / 平台习惯**：桌面支持键盘与多栏，触控支持较大目标与清晰返回；共享用户心智模型。
6. **Accessibility / 可访问性**：焦点、对比度、缩放、键盘、触摸目标与状态信息从初稿就设计，而非交付时补救。
7. **Restraint / 克制**：少即是多；避免每张卡片增加不同圆角、边框、色彩、阴影。

## 决策顺序

先问：用户当前任务是什么？→ 属于哪个 Pattern？→ 哪些信息必须可见？→ 对应平台的首选容器是什么？→ 哪些 Tokens/组件已有？→ 例外是否必要？

## 应该 / 不应该

| Do | Don't |
|---|---|
| 一个设置功能在全项目使用统一行结构 | 同类设置部分用卡片、部分用表单、部分用菜单且无原因 |
| 标准文字层级 + 限制内容宽度 | 靠任意字号和上下边距“微调到顺眼” |
| 以实际任务与平台习惯决定导航 | 窄窗口直接模仿一整套 iPhone 原生 UI |
| 明确“为何例外”并记录 | 把临时像素值变成永久隐性规范 |

## 验收

- 任意三页抽样：相同含义是否可辨认、相同 Token 是否一致？
- 能否解释每一个偏离默认组件/Pattern 的设计选择？
- 用户换设备是否仍认得当前功能及导航层级？
