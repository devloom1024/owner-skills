# 移动端 — 移动端与触摸交互

## 设计目标

- 主要任务可单手完成；一个屏幕只承载必要的决策与信息层级。
- 保持页面位置感，任何推入的二级页面都要有明确返回方式。
- 操作目标默认 ≥44×44 CSS px 作为推荐实践；WCAG 2.2 AA 的 24×24 CSS px（含例外）是另一层最低标准，不应混淆。
- 重要 CTA 避免被系统安全区、浏览器工具栏或软件键盘覆盖。

## 结构规则

- 默认 16px 左右内容边距，加上对应 safe-area inset。
- 长列表、表单单列；卡片不是强制容器，列表分组同样适用。
- 顶层导航数量少且稳定时可使用底部 Tab Bar；深层页面采用栈式返回。不是每个移动页面都需要底部栏。
- 易误触/毁坏性操作要求明确的按钮标签和风险提示，不只依赖左滑或长按。

## 触屏要求

- Hover 不能成为唯一入口；提供可见的“更多”按钮或上下文菜单。
- Swipe 可提升效率，但必须有等效可见操作；长按不作为发现功能的唯一方式。
- 模态 Sheet 高度适配屏幕与软键盘，滚动内容和固定动作区不可互相遮挡。
- 处理文字放大、语言变长、横竖屏和系统手势区域。

## 典型禁例

❌ 把桌面设置侧栏原样塞到 390px 的屏幕。  
❌ 所有按钮仅 28px 高且紧贴相邻控件。  
❌ 固定底部按钮遮挡内容，打开键盘后不可点击。
