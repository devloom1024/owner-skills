# 响应式 — 空间、输入与设备解耦

## 核心公式

**布局 = 可用容器空间 + 内容优先级；密度 = 输入方式 + 用户偏好；系统行为 = OS/宿主。**

- Electron 缩至 420px：通常需要折叠列，但未必应出现 iOS 底部导航。
- iPad 横屏 1100px 且触摸：可两栏，但按钮目标仍应足够大。
- 手机外接鼠标：布局紧凑仍需保持可触控，Hover 不可成为唯一入口。

三个维度（运行平台 / 空间 / 输入）的完整拆解见 [平台设计原则](../01-principles/platform-philosophy.md)。

## 空间范围（启发值而非设备身份）

| 可用容器宽度 | 暂定布局策略 | 不代表什么 |
|---|---|---|
| Compact: <600px | 单列、压缩次级操作、隐藏辅助面板 | 不自动判定为 iPhone |
| Medium: 600–1023px | 双栏可选、侧栏收起/抽屉、主内容优先 | 不自动判定为平板 |
| Expanded: ≥1024px | 多栏、持续性导航、可选详情侧栏 | 不自动判定为桌面鼠标 |

具体切换点以**内容开始拥挤**为判断；优先使用容器查询处理嵌入式 Pattern。上表不是要求所有项目硬编码相同 CSS 断点。

## 自适应顺序

1. 保留主要任务和主要内容。
2. 隐藏/折叠三级检查器、次要面板。
3. 将复杂工具栏操作合并到明确“更多”菜单，确保可达。
4. 列表由多列数据表适配为摘要行/卡片，重要字段不可丢失。
5. 仅在真正需要时修改导航容器；不能因为页面变窄丢失层级位置。

## 密度模式

| 模式 | 首选场景 | 默认控件/设置行 |
|---|---|---|
| Compact | 鼠标密集办公 UI | 36 / 48px |
| Comfortable | 手指输入、较大操作目标 | 44 / 56px |

混合输入设备建议允许用户切换密度或默认选择可触控尺寸；不要只使用 `(pointer: fine)` 判定“没有触摸”，因为它不一定代表所有可用输入设备。

## 测试矩阵（最低）

- 窄桌面窗口（约 420px，鼠标+键盘）
- 手机竖屏（约 390px，触摸）
- 平板（约 820px，触摸+外接键盘）
- 宽屏（约 1440px，鼠标）
- 200% 字体缩放、浅/深色、键盘导航、软键盘展开、安全区域。
