# 目录组织

## 层级与身份

采用默认生命周期时可按以下布局组织，不创建没有内容的目录：

```text
.agents/notes/
├── proposed/<class>/<record>.md
├── implemented/<class>/<record>.md
├── rejected/<class>/<record>.md
└── archived/<class>/<record>.md
```

- 生命周期表达提案、交付或否决；分类表达决策类型。`architecture`、`feature`、`process`、`testing` 等是可选分类，不是固定闭集；小项目可以省略分类层，不为普通记录扩展任意深度。
- 新记录可用 `YYYY-MM-DD-topic.md`，日期表示首次提出时间；保留已有稳定编号和日期含义。状态移动不重置身份或顺便改分类，确需重新分类时另说明理由并修复引用。
- 布局 README 用于规则说明，目录和搜索可以承担导航；已有索引按需维护，不强制新增或禁止集中式 `INDEX.md`。记录间使用可解析的链接，而不是只有标题或裸编号。

## 查找与有效规则

从根指令、Notes 入口和源码/文档引用找到实际记录根。递归搜索已确认的根并包含隐藏目录，避免工具默认跳过 `.agents/notes/`；对声明但被忽略规则漏掉的路径定向检查，不因此遍历全部缓存或第三方仓库。

读取实际路径上的根、`.agents/`、Notes、生命周期、分类等层级中存在的 `AGENTS.md`。不要求每层建立指令文件，也不因 Markdown 文件身份而自动继承 `docs/AGENTS.md`；显式引用的规则按声明范围使用。

## 单份记录移动与归档

1. 确定动作与依据：纯路径移动不改变决定；状态转换或归档先按 [生命周期](lifecycle.md) 判断，交付时按 [提案转换](transition.md) 收敛内容。核对源/目标有效规则，冲突时暂停受影响项。
2. 列出源/目标及项目已有的翻译、配对元数据和附件，作为同一记录集合处理，不因语言或分类另建 owner；共享附件保留其他使用方。不额外要求双语、sidecar 或特定门禁。
3. 同步可编辑记录的相对链接、活跃入链、导航及 owner 映射；当前理由指向当前 owner，历史引用明确其用途。
4. 首次归档仅执行项目封存流程允许的移动和元数据更新；已冻结记录不擅自编辑、重排、翻译、移动、删除或修复出链。受限项保留原状并报告，不通过换目录解除冻结。
5. 检查本次变更（含归档）的文件集合、身份、路径与状态含义、活跃引用及项目已有的配对/封存门禁。冻结记录的出链不要求反映当前代码；报告未验证项和引用限制，不跳过失败或放宽门禁求通过。
