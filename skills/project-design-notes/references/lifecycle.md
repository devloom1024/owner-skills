# 设计记录生命周期

先读取项目已有 ADR/设计生命周期，保留采纳、交付和冻结语义。无既有状态约定时，默认转换为 `proposed → implemented` 或 `proposed → rejected`：

- `proposed`：尚未完全交付的目标和方案，是验收来源，不是当前实现证据。
- `implemented`：决策已交付，内容反映实际行为与后果；未完成部分不能用该状态代表。
- `rejected`：保存否决理由和仍需保留的历史证据；不再推进的提案明确拒绝或撤回，不伪装成交付后再归档。删除不是状态转换的默认动作。

`accepted` 等采纳状态不等于已实现。没有单独采纳状态时，可在提案中记录已接受的决定及待完成工作；不要为了目录对齐提前标成 `implemented`，也不强制项目新增状态字段。

## 归档是维护状态

`archived/` 保存退出当前维护的历史记录，不是另一个当前事实 owner。仍有效的理由或部分替代的约束保持活跃；完整替代或失去未来指导价值且仍有历史价值时，才按项目规则归档。没有年龄、长度或数量阈值。

保留原始决定状态，归档日期等维护信息另行记录。例如项目可以在 `archived/` 下保留 `Status: implemented`，不应为了与目录同名改成 `Status: archived`。进入历史区不意味着已采纳方案曾交付，也不等于作出新的决策。

交付收敛见 [提案转换](transition.md)；目录移动与封存检查见 [目录组织](organization.md)。
