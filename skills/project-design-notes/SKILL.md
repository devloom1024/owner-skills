# 项目设计记录

使用设计记录保存代码、测试和当前文档无法表达的长期理由。它是设计阶段和实现收敛阶段的事实来源，不是当前运行行为的替代品。

## 生命周期

```text
proposed → implemented
proposed → rejected
implemented → archived
```

- `proposed`：MVP 或方案尚未完全实现。
- `implemented`：决定已经交付，内容使用现在时态描述实际行为。
- `rejected`：方案被否决，保留否决理由。
- `archived`：只保留历史价值，不再作为当前依据。

## 工作流

1. 阅读相关当前子系统、包 README、AGENTS.md 和已有设计记录。
2. 搜索可能被替代的记录。
3. 使用 `templates/proposed-note.md` 创建问题、目标、范围、方案、替代方案、验收标准、风险和未决问题。
4. 实现时对照验收标准，记录偏差和新增决定。
5. 交付后把提案转换为 `implemented`，更新当前子系统和包 README。
6. 被拒绝或被替代时记录原因和链接关系。

## 边界

设计记录可以描述未来目标；当前事实文档只能描述有代码、测试、配置或生成器证据的行为。默认只读，生命周期迁移需要明确授权。
