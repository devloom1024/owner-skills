# 项目 PR 描述

PR 描述是变更证据的入口，不是实现过程的流水账。

## 结构

1. 目标和用户可见结果；
2. 实现范围和关键设计；
3. 文档、契约和升级影响；
4. 测试与验证命令；
5. 未运行的检查和未验证环境；
6. 设计偏差、已知风险和后续工作；
7. 相关 Issue、设计记录和文档链接。

## 工作流

读取完整 diff、设计记录、`project-change-sync` 报告和测试输出。使用具体的 before/after 行为，不把推断写成结果。变更后重新读取 PR 描述并更新已过期的范围、测试和风险。
